# Feature Spec: Contract PWA
**Created:** 2026-10-30  
**Status:** Approved  
**Project type:** Greenfield  
**Project path:** `/Users/tony/contract-pwa`

## Problem Statement

Ручное заполнение договора аренды ТС и заявления на ввод/вывод ТС из ОСГОП по готовым Word/PDF занимает время и провоцирует ошибки в повторяющихся полях. Нужен личный офлайн-инструмент: форма → готовый документ в PDF или DOCX.

## Users and Roles

- Единственный пользователь — владелец (Арендатор / ИП). Авторизация не нужна.

## Scope

### In scope (this build)

- Отдельное PWA (`/Users/tony/contract-pwa`), полностью офлайн после первой успешной загрузки ассетов.
- Два шаблона, подготовленные из имеющихся заполненных примеров:
  1. **Договор аренды ТС без экипажа**
  2. **Заявление на ввод/вывод ТС из договора ОСГОП** (режимы: включение и исключение)
- Форма → подстановка в шаблон → скачивание **PDF** или **DOCX**.
- Арендатор в **договоре** зафиксирован в шаблоне (не в форме).
- Автосохранение черновика формы в `localStorage`.

### Out of scope (future / not planned)

- Авторизация, мультипользовательность, облако.
- ЭЦП, email/мессенджеры.
- Интеграция с `site-vue` / CRM.
- Генерация Акта приёма-передачи (остаётся только упоминание в тексте договора).
- Редактирование юридической части вне плейсхолдеров.

### MVP vs stretch

- **MVP:** два шаблона + форма + PDF/DOCX офлайн + черновик.
- **Stretch:** история договоров; поиск по ГРЗ; отдельный акт приёма-передачи.

## Functional Requirements

### Happy Path

1. Открыть PWA (браузер или установленное приложение).
2. Выбрать тип: «Договор аренды» или «Заявление ОСГОП».
3. Для заявления выбрать режим: **Включение** или **Исключение**.
4. Заполнить поля; черновик автосохраняется (debounce 400 ms).
5. При повторном открытии того же типа/режима — черновик восстанавливается.
6. Нажать «Скачать PDF» или «Скачать DOCX».
7. Получить файл с подставленными значениями; имя файла по правилам ниже.
8. «Очистить форму» сбрасывает поля и черновик текущего типа/режима (с confirm).

### Edge Cases and Error Handling

1. **Пустые обязательные поля** — при submit показать inline-ошибки у полей; кнопка экспорта остаётся активной, но генерация блокируется до исправления.
2. **Дата «с» > «до»** — ошибка на диапазоне срока аренды; экспорт заблокирован.
3. **Первый визит полностью офлайн (нет кеша)** — страница с текстом «Нужен интернет один раз для установки»; после кеша SW — обычная работа без сети.
4. **localStorage недоступен / QuotaExceeded** — форма работает без автосохранения; показать неблокирующее предупреждение один раз за сессию.
5. **Смена типа документа / режима ОСГОП** — текущий черновик уже сохранён под своим ключом; форма загружает черновик нового типа/режима (или пустую, если его нет). Без confirm.
6. **Номер договора аренды** — поле read-only, всегда равно ГРЗ (после trim + uppercase).
7. **Повторный экспорт** — разрешён; каждый раз новый файл с тем же правилом имени.
8. **ОСГОП: режим Включение** — в документ попадает только таблица включения; таблица исключения не выводится. **Исключение** — наоборот.

### Data Validation Rules

Общее: значения после `trim`; пустая строка = отсутствует.

**Даты:** ввод через `<input type="date">` (локальная таймзона устройства); в документе формат `ДД.ММ.ГГГГ`. Для шапки договора «„26“ октября 2026 года» — отдельный форматтер из той же даты.

**Договор — обязательные:**

| Поле | Правило |
|------|---------|
| ГРЗ | непустой; в форме uppercase; без жёсткого regex (свободный текст) |
| № договора | = ГРЗ, read-only |
| Дата договора | валидная дата |
| ФИО арендодателя | min length 1 |
| Дата рождения | валидная дата |
| Адрес регистрации | min length 1 |
| Марка и модель | min length 1 |
| VIN | min length 1 |
| Год выпуска | целое 1900–2100 |
| Цвет | min length 1 (свободный текст) |
| Тип двигателя | min length 1 (свободный текст) |
| СТС | min length 1 |
| ПТС | min length 1 |
| Срок с / по | валидные даты; с ≤ по |
| Цена руб/сутки | целое число > 0 |

**Заявление ОСГОП — обязательные:**

| Поле | Правило |
|------|---------|
| Номер договора ОСГОП | min length 1 |
| Название клиента | min length 1; префилл `ИП Аверьянова М.Ю.` (editable) |
| Дата включения/исключения | валидная дата |
| Строка ТС: марка/модель, ГРЗ | min length 1 |
| Строка ТС: пассажировместимость, посадочные места | целое ≥ 0; обязательны |
| Строка ТС: год выпуска | целое 1900–2100; обязателен |
| Строка ТС: вид перевозок | выбор из справочника (как в примере) или свой текст; обязателен |
| Минимум строк ТС | 1 |

### Хранение черновика

- Только `localStorage`.
- Ключи: `contract-pwa:draft:lease`, `contract-pwa:draft:osgop:include`, `contract-pwa:draft:osgop:exclude`.
- После успешного скачивания черновик **не** очищается (можно править и скачать снова).
- Очистка — только кнопкой «Очистить форму».

### Имена файлов

- Договор: `Dogovor_{plate}_{YYYYMMDD}.{pdf|docx}`
- Заявление: `Zayavlenie_OSGOP_{include|exclude}_{YYYYMMDD}.{pdf|docx}`

### Подготовка шаблонов (обязательный шаг сборки)

Исходники лежат в `templates/source/`.

1. Из заполненного PDF договора сделать **мастер DOCX** с плейсхолдерами `{{...}}` (текст договора воспроизводится по примеру; визуал — деловой документ A4).
2. Из DOCX заявления убрать заполненные значения, поставить плейсхолдеры; таблицы включения/исключения — через цикл/условия шаблонизатора.
3. Оба мастера (`lease.docx`, `osgop.docx`) кладутся в `public/templates/` и кешируются SW.
4. **DOCX-экспорт:** заполнение мастера (docxtemplater или аналог).
5. **PDF-экспорт:** тот же заполненный контент рендерится в печатный HTML (или из DOCX→PDF на клиенте); без сервера. Конкретная библиотека — решение brainstorm, критерий: офлайн + кириллица.

## Non-Functional Requirements

- Offline-first: SW кеширует app shell + шаблоны.
- Installable PWA (`manifest`, иконки).
- Без аналитики/трекеров.
- Работает в актуальных Chrome (desktop/Android) и Safari iOS; без установки — полноценно в браузере.
- UI: одна колонка на mobile; labels всегда видимы; язык — русский.
